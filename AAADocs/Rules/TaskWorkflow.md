# 任务推进与协作

接需求、分配、并行开发或占用 UE／构建时读本文。

目标：让写代码的时间多于沟通的时间。规则只防真实冲突（同一文件、同一共享资产、同时构建），其余交给执行者自己判断。

## 分工

### 按需求分配，不按模块分配

- 一个需求或一条功能线只交给**一个负责人**。负责人对这条链上涉及的所有源码、蓝图、资产和脚本都有写权，从设计做到自测，不再拆给多个模块各写一段。
- 只落在一个模块内的需求，负责人就是该模块的长期会话。
- 跨模块需求，统筹指定一个负责人，通常选改动最多的那个模块。其它相关模块不参与实现。
- 同一条依赖链上的工作（A 的输出是 B 的输入）不拆给多个人。只有真正互不依赖的需求才并行。

### 角色

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| 统筹 | 拆需求、指定负责人、维护[看板](../Coordination/Board.md)、仲裁冲突、合并后集成验证、Git 交付 | 不逐步审批，不代写实现，不转发未变化的背景 |
| 负责人 | 读代码、定方案、实现、编译、跑相关测试、交付回执 | 不等逐步批准；不为证明合规写额外报告 |
| 模块会话 | 负责本模块的单模块需求；在跨模块需求中被问到时回答本模块的接口和约束；维护本模块的 Obsidian `结构.md` | 不在别人的需求里抢写代码，不要求别人先等自己核收 |

- 负责人改到别的模块时，先读该模块的 Obsidian `结构.md` 和受影响调用链。拿不准职责边界时，直接问该模块会话一次，问题写具体。对方答复后就继续做，不需要来回确认。
- 交付时，统筹判断改动是否触及某模块的核心状态或接口。触及时让该模块会话做一次评审，评审只看 diff。
- 模型设置：统筹与模块会话用 gpt-6-astra；模块组长 xhigh，Fast 关闭。

### 工作协调授权

- 用户将工作协调交给统筹决定：负责人分配、独立需求并行、同文件／共享资产冲突、构建与我方 UE 排期、接口确认、交付评审及先后顺序。组长遇到这些问题直接找统筹，不再请求用户批准。
- 用户授权统筹与项目相关既有会话发送必要的协调、接口咨询和交付消息；组长可为这些事项联系统筹或相关负责人。这项授权跨需求持续有效，不因接续下一条需求重新询问，也不为发信单独向用户申请。
- 已挂起的同类协调授权问题按此授权继续，不再等待用户重复回答。收到协调决定直接执行，仍只在阻塞、需要决定或交付时发消息。
- 该授权不改变下节的用户决策边界，不允许覆盖用户未保存工作、终止用户编辑器或扩大需求范围。

### 需要用户决定的事

以下情况给出具体场景和选项请用户决定，只暂停相关工作线：需求歧义、玩法／输入／镜头行为、实质兼容选择、UE／GAS 引擎修改、可能丢失现有工作。技术实现细节由负责人自己决定。

## 并行与冲突

- 开工前在[看板](../Coordination/Board.md)的占用表登记一行：负责人、需求、要改的文件或目录、要动的共享资产。做完删掉这一行。
- 只有两种情况算冲突：
  - 两人要改同一个文件。
  - 两人要用 UE 同时写同一个共享资产，比如同一张地图、同一个 Skeleton 或 Master 材质。
- 遇到冲突，后来的人先找占用者商量顺序；谈不拢找统筹。没有冲突就直接开工，不需要谁批准。
- 不做冻结、前像／后像、哈希身份、保护集合或租约。文件变化以 Git diff 为准。
- 用户手动编辑过、还没提交的文件，改之前先问用户。

## 构建与 UE

- 负责人可以自己做增量编译和跑相关自动化测试，不必等集中窗口。
- 同一工作树同一时间只跑一个 UBT 构建。开始前在占用表登记"构建中"，结束后删掉。
- 启动会加载项目 DLL 的 UE 实例前，确认没有别人在构建。互斥资产可以用多个 Editor／CLI 并行，日志和输出目录分开。
- 不覆盖用户未保存的工作，不 SaveAll。我方测试 UE 可自主启动、退出和异常收尾，只处理我方实例；用户自己开的编辑器不碰。
- 优先用可用的 MCP；工具没暴露不等于数据不存在。
- 确需新增大体积数据（比如几 GB 的派生资源或整树复制）时，先告诉用户范围和体量，由用户决定。

## 沟通

- 默认不发消息。只在三种情况发：真实阻塞、需要别人做决定、交付。
- 消息写清楚三件事：发生了什么、需要对方做什么、证据在哪。一般不超过 200 字。
- 收到消息照做即可，不需要回"已收到"或"已核收"。
- 交付回执固定格式：

```
需求：<名称>
改动：<文件列表或 commit>
验证：<编译／测试／运行结果，附日志路径>
未验证：<哪些没测，为什么>
需要：<统筹或用户下一步要做什么，没有就写"无">
```

## 会话

- 单模块需求复用该模块的长期会话；会话路由见[会话路由](../Coordination/Module_Conversation_Routing.md)。
- 跨模块需求由负责人在自己的会话里完成。会话被压缩或上下文混乱时，从需求记录和代码重新开始，不从聊天历史恢复。
- 长期知识写进模块的 Obsidian `结构.md`，不依赖会话记忆。

## 过渡

在途工作按本文继续：

- 已经冻结的源码，原作者或新指定的负责人直接继续改，不需要再办归还手续。
- 正在跑的 UE／构建窗口正常收尾即可。
- 旧排程里的保护集合、身份和余额不再维护；统筹把在途需求迁到[看板](../Coordination/Board.md)后，旧排程只作历史参考。
