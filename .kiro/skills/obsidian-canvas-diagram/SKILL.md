# GGYGO 架构笔记

目标目录：F:/Obsidian/Doc/lyra学习笔记/GGYGO架构规划。职责、事实、接口、关键实现和未验证边界要能沿图文查到；不把计划画成已经实现。

## 工作方式

- 已知目标文件就直接读受影响图文及必要源码；模块不明确时用计划蓝图.md定位。仅跨模块契约变化才读直接相邻模块，不为小修强制读全套计划与总览。
- 修改已有图保留可复用的 ID、节点布局、颜色和原连接，只改变真实需要更新的内容。
- 文档以完整需求开发且约定验证完成后的检查点更新。过程只留现有任务状态，不逐步骤重画、重复记录历史或声称局部移交等于整需求完成。

## 交付内容

- 每模块在自身目录有配套结构.md、结构 Canvas 与必要的主流程／子图；沿既有命名和导航，不另造平行目录。
- 结构图说明持有／继承／调用／数据关系。关键接口必须写“输入 → 作用 → 输出或副作用”，不能只列名字，也不复制整个头文件。跨模块接缝链接对方结构.md。
- 流程图说明“触发者 → 真实接口 → 状态／结果”，边写条件或传递内容；静态类关系留结构图。关键算法不压成一句“更新”，也不把每个小步骤拆成四处牵线的块。
- Camera 的 Component／Stack／Mode／View 关系、栈实例复用与混合，以及动画曲线来源／基线／差分／消费等重要实现按影响展开。优先复用现有实现文档；流程复杂且可独立理解时才拆子图。

## 按需细则与核对

- 新建／重排模块图文或接口内容：读 [references/module-notes.md](references/module-notes.md)。
- 编辑 .canvas：读 [references/canvas.md](references/canvas.md)，核合法 JSON、唯一 ID、边端点／标签、链接存在、布局与正文容量。
- 只改 Markdown 不加载 Canvas 格式说明；只修链接不重做模块设计。完成后读回受影响文件，对照源码／实际验证核事实，简短汇报变化和未验证项。
