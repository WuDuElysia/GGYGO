# 模块图文内容

## 结构.md 与结构图

结构.md 说明边界、核心类／数据、状态与资源归属、关键接口及交互。接口描述参数或输入、作用、输出／副作用、有效期与清理；只列对模块或跨模块协作关键的内容。

结构 Canvas 用类、接口、资产或独立职责作节点，边写持有／继承／调用接口／发布数据等真实关系。图内必须保留必要接口及作用，不能让读者全部跳 Markdown 才知道调用什么。当前与目标类分开，目标显式标未实现。

Camera 至少讲清 CameraComponent→CameraModeStack→CameraMode→CameraModeView，以及 Hero／GA 对有效模式的影响。跨模块节点只展开接缝并链接对方结构.md，不在多图重复抄整套模块。

## 流程与关键实现

主流程表达引擎实际时序：“谁触发→调用哪个接口（必要输入）→产生何种状态／结果”。每次关键跨模块跳转有真实接口名；不存在的接口标目标，不写空泛“处理／更新”。分开主路、拒绝／失败、明确就绪、收尾等不同语义。

对影响画面、预测、时序或恢复的实现，配合同目录 Markdown／必要子图说明关键机制，例如：
- CameraStack 的实例复用、入栈贡献和混合顺序；
- 动画曲线的来源标记、基线重置、差分、XYZ 消费及目标拆环。

保留关键条件与接口，不展开无关样板。少量紧密步骤放一个块；独立且复杂的问题才拆子图，子图给主图入口／出口。计划_*.md保留设计依据、算法与待验任务，不重复变更日记。

## 导航与事实

沿计划蓝图.md的模块目录和已有文件名扩展；根只负责导航／跨模块关系／实施状态。入口链接结构 Markdown、结构图和流程图，相关图互链；用可解析 wikilink，例如 [[Camera/结构|Camera结构]]、[[GGYGO_结构_AbilitySystem.canvas|结构图]]。

先当前事实，再原因与约束。实际类／API／Tag／资产路径由源码与已读回证据核实，关键实现不能凭旧图记忆。区分已验证、未运行、失败与计划，未完成描述当前后果而非单写“后续”。无事实变化不空改总览；只汇报受影响图文及实际核对范围。
