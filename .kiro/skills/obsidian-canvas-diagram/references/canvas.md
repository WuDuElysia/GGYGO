# Canvas 编辑与检查

.canvas 是 JSON；正文可以是 Markdown，文件外不加 Markdown 外壳。沿目标图既有节点类型，GGYGO 默认以 text 为主，颜色、尺寸和布局优先沿同类节点，不机械统一全部旧图。

最小格式：

```json
{
  "nodes": [
    {"id":"entry","type":"text","text":"入口：触发者／接口／结果","x":0,"y":0,"width":420,"height":260},
    {"id":"result","type":"text","text":"结果及职责边界","x":520,"y":0,"width":420,"height":260}
  ],
  "edges": [
    {"id":"entry-result","fromNode":"entry","fromSide":"right","toNode":"result","toSide":"left","label":"实际调用或传递内容"}
  ]
}
```

## 内容与布局

- 结构图按依赖／持有关系聚类；依赖图声明 A→B 表示 A 依赖 B，调用边则写实际方向及接口。不把所有 include 画出来。
- 流程主链通常左→右或上→下；分支旁置并标条件，必要回流标重试／收尾等真实语义。多个生命周期不要合为无意义“完成”。
- 一个子图展开一个问题，说明主图入口／出口并提供返回链接。线交叉密集时评估职责或子图，不靠无限放大节点。
- 节点能容纳正文，避免重叠／边穿过正文。新增颜色复用目标图语义；常见6说明、4基础、5核心、3分支、1事件，但不据此重染旧图。

## 验证

用 JSON 解析器检查文件；同文件节点／边 ID 唯一，fromNode/toNode 必须存在。检查新增边有准确 label、方向合理，新增 wikilink 指向存在或同时创建的文件。移动文件时查旧链接、file 节点路径及同名结构.md歧义。

保留原 ID／坐标／无关正文，读回检查转义、截断、尺寸及新增区域。解析成功不等于实际视觉验收；未做原生 Obsidian 渲染就如实说明。复用现有校验脚本，不为普通编辑新增框架／全源哈希。
